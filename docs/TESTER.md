# Tester SkanEcom soi-même

Cinq boutiques de démonstration tournent avec la même application, chacune avec son gabarit :

| Adresse | Boutique | Gabarit |
|---|---|---|
| http://mode.localhost:4200 | Maison Selma — prêt-à-porter | Immersif |
| http://maymar.localhost:4200 | Maymar — bagages | éditorial |
| http://quincaillerie.localhost:4200 | Quincaillerie du Sud — outillage | Commerce |
| http://beaute.localhost:4200 | Yasmine Beauté — soins et parfums | Monoproduit |
| http://maison.localhost:4200 | Dar Alia — maison et décoration | Bento |
| http://console.localhost:4200 | la console de mise en place | — |

Tout tourne sur ta machine : une base Postgres, l'API (PostgREST et GoTrue, comme chez Supabase) et la vitrine compilée pour Cloudflare Workers. Rien n'est ouvert au réseau : la vitrine n'écoute que sur `127.0.0.1`.

Les photos des boutiques sont des photos de démonstration libres de droits (`supabase/fichiers-demo/CREDITS.md`) : elles restent jusqu'à la fin du développement. Les produits de Maymar affichent « photo à venir » en attendant ses vraies photos.

## 1. Installer, une seule fois

Il faut **Linux** (Ubuntu 24.04 ou Debian 12) sur un processeur **x86_64**, ou **Windows avec WSL2**. Sur Mac, pas encore : deux outils téléchargés (PostgREST, GoTrue) sont compilés pour Linux.

**Windows** : dans PowerShell ouvert en administrateur, `wsl --install -d Ubuntu-24.04`, redémarrer, ouvrir « Ubuntu » dans le menu Démarrer, puis continuer ci-dessous dans ce terminal.

Dans le terminal (Ubuntu, Debian ou WSL) :

```bash
# Postgres 16 avec pgTAP (et pg_prove pour les tests), et les petits outils
sudo apt update
sudo apt install -y postgresql-16 postgresql-16-pgtap libtap-parser-sourcehandler-pgtap-perl curl unzip xz-utils git

# Node 22 (par nvm), puis Bun
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash
source ~/.bashrc
nvm install 22
curl -fsSL https://bun.sh/install | bash
source ~/.bashrc
```

Sur Debian 12, `postgresql-16` vient du dépôt de Postgres (apt.postgresql.org) : suivre la page « Linux downloads (Debian) » de postgresql.org, puis la même commande `apt install`.

## 2. Lancer

```bash
git clone https://github.com/saouthq/skanecom.git
cd skanecom
git checkout claude/gallant-hawking-gi9xv0
outils/essayer.sh
```

`outils/essayer.sh` vérifie d'abord les prérequis (et dit quoi installer s'il en manque un), recrée la base avec le jeu de démo, démarre l'API, compile la vitrine puis la lance. Compter quelques minutes la première fois : il télécharge PostgREST, GoTrue (empreintes vérifiées) et les dépendances de l'application. Quand il affiche les quatre adresses, les ouvrir dans **Chrome, Firefox ou Edge** (ils savent que `*.localhost` est ta machine).

- **Windows (WSL)** : ouvrir les adresses dans le navigateur de Windows. Si la page ne s'ouvre pas, activer le réseau partagé de WSL : créer `%UserProfile%\.wslconfig` avec les deux lignes `[wsl2]` et `networkingMode=mirrored`, puis `wsl --shutdown` dans PowerShell et relancer.
- **Relancer après une modification**, ou pour repartir d'un jeu de démo propre : Ctrl+C, puis `outils/essayer.sh` à nouveau.
- **Arrêter** : Ctrl+C (la vitrine), puis `outils/essayer.sh arreter` (la base et l'API).
- **Autre port** : `PORT_VITRINE=4300 outils/essayer.sh`, et les adresses deviennent `…localhost:4300`.

## 3. Quoi essayer

**Maison Selma** (Immersif, sur les composants éditoriaux)
- L'ouverture prend tout l'écran, l'en-tête posé sur la photo ; il redevient opaque quand on descend.
- **La pièce de la saison**, juste après : la robe à bretelles en grand, choisir M, **Ajouter au panier** sans quitter l'accueil (au téléphone, la barre d'achat colle en bas une fois le bloc passé).
- Les nouveautés et les collections glissent : au doigt, ou par les flèches (le compteur suit).
- **Le lookbook** : la carte du combishort est ouverte sur la photo ; Échap la ferme, Entrée sur le point la rouvre ; la liste à côté mène à la fiche. Dans l'éditeur (`gerant@selma.test`, Vitrine → Accueil → Lookbook), cliquer la photo pose un point, le glisser ou ses flèches le déplacent (Maj : 5 % d'un coup), chacun choisit sa pièce.
- Survoler une carte : la deuxième photo du produit apparaît (robe à bretelles, pull mérinos, polo).
- Catalogue → **Filtrer** : cocher une taille ; le tiroir reste ouvert pour cocher la suivante ; « Voir les N résultats » le referme. Retirer un filtre par sa puce. Trier par prix.
- Fiche produit : choisir une taille, **Ajouter au panier** → le panier s'ouvre, avec la vignette et la jauge « plus que … pour la livraison offerte ».
- **Avis clients** (les trois boutiques ont le module) : la « Robe à bretelles en lin » montre sa note sur sa carte du rayon Robes et sous le titre de sa fiche (4,7 · 3 avis) et, plus bas, les avis vérifiés, la répartition des notes et la réponse de la boutique. Au backoffice de Selma (`gerant@selma.test`), **Avis** : l'avis de Yosra attend la relecture ; répondre, publier, ou écarter avec un motif. Une commande livrée propose, dans « Mes commandes », « Donner mon avis » sur chaque article (cinq étoiles, un mot facultatif) ; Réglages → Service client → Avis clients : relu avant publication, ou publié aussitôt.
- **Site vitrine** (aucune boutique ne l'a d'office) : au backoffice de Dar Alia (`gerant@dar-alia.test`), Réglages → Commandes → « Le site » → « Un site vitrine », Enregistrer. Sur la vitrine, plus de panier ; une fiche propose « Écrire sur WhatsApp » (le message nomme la pièce et sa référence), l'appel, l'e-mail ; /commande dit comment joindre la boutique. Revenir à « Une boutique en ligne ».
- **Achat express** (Selma a le réglage) : sur une fiche, **Commander maintenant** mène droit à la commande avec cet article seul ; le panier reste tel quel. Sur téléphone, la barre collante propose les deux (l'icône du panier, « Commander maintenant »). Au backoffice, Réglages → Commandes → « Depuis la fiche d'un produit » : par le panier, ou achat express en plus.

**Quincaillerie du Sud** (Commerce, sur les composants techniques)
- L'accueil s'ouvre sur la recherche : taper `perc` dans la grande barre, les pièces s'affichent pendant la frappe ; les rayons en raccourcis dessous, les services en bande.
- Sous les services, **trois bannières qui défilent** (une toutes les six secondes) : les flèches, les points, la pause ; au téléphone, les faire glisser au doigt. Un geste arrête le défilement. Entrée (ou un clic) sur la première mène au rayon Scies.
- **Tous les rayons** : le grand menu ; survoler « Quincaillerie », ses sous-rayons paraissent. Au clavier : Tab jusqu'au bouton, Entrée, Tab, ↓, Tab entre dans les sous-rayons ; Échap referme.
- **Comparer** : dans Perceuses et visseuses, survoler une carte, cocher « Comparer » sur deux pièces ; la barre du bas les montre ; « Comparer (2) » les met côte à côte (« Seulement les différences », « Retirer »).
- Au téléphone : la barre d'onglets en bas (Accueil, Rayons, Chercher, Compte, Panier) ; elle se retire sur une fiche.
- Chercher dans la grande barre, par référence ou par nom : `PV14`, `casque`, `forets`.
- Rayon Outillage électroportatif : colonne de filtres à gauche (diamètre, version, prix, stock).
- Sur une carte à une seule déclinaison, **Ajouter** met directement au panier.
- Fiche perceuse : choisir « Kit 2 batteries », la référence suit la version.
- Ouvrir trois ou quatre fiches, puis une autre : en bas, **Vus récemment** reprend les pièces vues, la plus récente d'abord (prix et stock du moment ; « Effacer » vide la liste). La page introuvable le propose aussi.

**Yasmine Beauté** (Monoproduit) : l'accueil est la page de vente de son sérum éclat — choisir « 3 pièces » (à la souris, ou aux flèches) : « Commander · 147,000 TND », le formulaire dessous dit « Votre offre : 3 pièces » et son récapitulatif « Prix par 3 », 177,000 barré ; « Commander » y mène, le curseur dans le téléphone ; la commande se passe là, sans toucher au panier. Puis l'huile de figue de Barbarie — 30 ml change le prix ; le vernis à ongles, ses teintes en pastilles (au clavier : Tab depuis le titre, Entrée ; « Corail » : plus que 2) ; le savon à l'huile d'olive, parfum « Fleur d'oranger » épuisé : « Prévenez-moi de son retour » ; ses prix par quantité (3 pour 30,000, 6 pour 54,000) : choisir « 3 pièces », ajouter, le tiroir et la commande disent « 3 pour 30,000 ».

**Dar Alia** : l'accueil en Bento — une mosaïque de tuiles, l'en-tête flottant en pilule ; à côté de l'ouverture, la pièce à la une, le paiement à la livraison et la note de ses huit avis ; cinq rayons (le premier sur deux rangées), « Nos essentiels », les avis, puis le kilim tissé main — 120 × 180 cm : 349 dinars, plus que 2 ; 160 × 230 cm, épuisé, barré ; les serviettes de table en lin, leurs couleurs en pastilles (Sable, Écru), au clavier ; au téléphone, le menu → Luminaires.

**L'éditeur de la vitrine** — au backoffice (http://console.localhost:4200), `gerant@dar-alia.test`, mot de passe `equipe-locale-skanecom` (double authentification proposée à la première connexion, « Plus tard » la reporte), onglet **Éditeur de la vitrine** (plein écran ; « ← Backoffice » pour revenir) : à droite, la vraie vitrine de Dar Alia, sur ordinateur ou téléphone, et la page voulue (accueil, catalogue, une fiche, la commande). À gauche, chaque réglage s'y voit aussitôt : la structure (éditoriale, Bento — la mosaïque de Dar Alia —, technique ; ses coins et ses boutons conseillés viennent avec), une ambiance (« Nuit » passe en mode sombre), le fond, l'accent (et tout autre au nuancier ; la lisibilité est mesurée dessous), les treize couleurs une à une, la police des titres (onze familles, Bodoni Moda, Fraunces, Syne…) et du texte, la taille et l'écriture des titres, les coins, la forme et la couleur des boutons, les cartes, le format des photos, l'espace entre les sections, les animations. Ctrl+Z défait, Ctrl+Maj+Z refait ; « Avant / après » montre la version publiée. Chaque geste s'enregistre seul dans un brouillon que les visiteurs ne voient pas ; « Sur votre téléphone » donne le lien qui l'ouvre ailleurs, avec un bandeau. **Publier** le met en ligne ; « Revenir à la version publiée » l'abandonne. Le panneau **Accueil** : les sections de haut en bas — montez-en une (au clavier : Tab jusqu'à « Monter », Entrée), retirez-la puis « Rétablir », ajoutez-en depuis « Ajouter une section », changez la photo d'ouverture ; l'aperçu suit chaque geste sans recharger. Survolez une section de l'aperçu : son nom s'affiche ; cliquez-la : ses réglages s'ouvrent à gauche ; tapez un titre, il paraît une seconde plus tard. Ou écrivez sur la vitrine même : cliquez le titre de l'ouverture dans l'aperçu, tapez (le champ « Titre » suit, à gauche), Entrée pour finir ; cliquez le bouton, tapez, Échap : il redit ce qu'il disait. Le panneau **En-tête et pied** : tapez une annonce (elle paraît en tête de la vitrine), un compte Instagram (« pas un compte » est refusé sous le champ ; « @atelier.alia » passe), le bouton WhatsApp ; cliquez le pied de page de l'aperçu, son panneau s'ouvre. Le panneau **Pages** : ouvrez « Le magasin » (la vitrine du cadre va sur la page), changez une phrase, elle paraît une seconde plus tard ; « Livraison et retours » (un modèle composé des réglages) crée une page neuve, encore hors ligne mais visible à côté ; les flèches rangent les pages (le pied de page suit, aussitôt) ; « Retirer… » la retire de la boutique, après confirmation. **Publier** met le style, l'accueil, l'en-tête et le pied, et les pages en ligne d'un coup.

**Maymar** : l'accueil, puis la fiche « Valise rigide ABS 4 roues » : choisir Grande 75 cm et Bordeaux — cette combinaison est épuisée, la fiche le dit et le bouton se désactive. **Commander** (les trois boutiques) : dans le panier, **Commander**. Saisir un numéro tunisien (par exemple 20 123 456) et « Recevoir le code » : aucun SMS ne part, le code s'écrit dans `.outils/sms.log` (`tail -f .outils/sms.log` dans un autre terminal). **Sur téléphone** : dans Chrome ou Edge, F12 puis l'icône téléphone (« Toggle device toolbar »), choisir un modèle et recharger : menu en tiroir, galerie à faire glisser, barre d'achat collante en bas de la fiche. (Un vrai téléphone ne peut pas joindre la vitrine : elle reste sur ta machine.)

**Backoffice** — http://console.localhost:4200, mot de passe `equipe-locale-skanecom` : `appels@maymar.test` (confirmation des commandes) ou `gerant@maymar.test` (propriétaire, double authentification proposée à la première connexion, « Plus tard » la reporte). Les onze commandes de démonstration de Maymar : appeler, confirmer, expédier, noter une livraison ou un refus ; à l'étape « À préparer », « Bordereaux » les imprime deux par feuille (ou en PDF). Onglet **Catalogue** : filtrer (en vitrine, brouillons, stock bas), ouvrir un produit, enregistrer une réception ou un inventaire, changer un prix, ajouter une couleur, ajouter des photos (glisser-déposer ; les ranger, les légender, en attitrer une à une couleur) ; **Nouveau produit** : un nom, un prix, ses tailles et couleurs, et toutes les déclinaisons sont créées (en brouillon, sans stock). Onglet **Catalogue → Caractéristiques** : définir une caractéristique (« Volume », en L, un nombre, filtrable, rayon Valises), puis la saisir sur la fiche d'un produit (section « Fiche technique ») ; la vitrine l'ajoute au tableau de la fiche et aux filtres du rayon. La quincaillerie de démonstration en a déjà : http://quincaillerie.localhost:4200/categorie/outillage (filtres « Alimentation », « Puissance », pastilles sur les cartes). **Quantité minimale** : les vis à bois au détail s'y vendent par 20 au moins (http://quincaillerie.localhost:4200/produit/vis-bois-tete-fraisee : le sélecteur part de 20, la boîte de 200 revient à l'unité) ; sur la fiche d'un produit du backoffice, le champ « Minimum » de chaque déclinaison. **Comptes professionnels** (la quincaillerie a le module) : dans http://quincaillerie.localhost:4200/compte, connecté par SMS, « Demander un compte pro » ; au backoffice (un propriétaire de la quincaillerie), Clients → « Comptes professionnels » : la demande de la Plomberie Ben Salem attend, valider la vôtre ; revenir sur la perceuse : « Votre prix pro », le prix public barré, puis « Tarif professionnel appliqué » au tunnel ; le champ « Prix pro » de chaque déclinaison sur la fiche produit du backoffice. **Devis** (la quincaillerie a le module) : remplir le panier, puis dans le tiroir « Demander un devis » ; au backoffice, `gerant@quincaillerie.test` (propriétaire de la quincaillerie, double authentification proposée à la première connexion, « Plus tard » la reporte) ouvre « Devis » : la demande du plombier et la vôtre attendent ; appliquer une remise, offrir la livraison, « Envoyer le devis » (le message WhatsApp est prêt) ; de retour dans « Mes commandes », « Mes devis » : « Accepter et commander », et le tunnel passe la commande aux prix du devis. Un devis prêt attend déjà l'électricienne du jeu de démo : ouvrir http://quincaillerie.localhost:4200/commande?devis=DEV-00002 dans une fenêtre privée, se connecter sur place avec le 22 345 002 (pro validée ; le 98 765 001 est le plombier), et le devis s'ouvre à ses prix. Onglet **Clients** : l'onglet « Avec refus », une fiche, la bloquer (un motif est demandé), la rétablir ; depuis une commande, « Voir sa fiche ». Onglet **Équipe** (le gérant) : inviter un employé, ouvrir son lien dans une fenêtre privée, changer son rôle, lui retirer l'accès.

**Console** — http://console.localhost:4200, `admin@skanecom.test`, mot de passe `console-locale-skanecom` (base locale seulement). À la première connexion, scanner le QR code avec une application d'authentification (Google Authenticator, Microsoft Authenticator, 1Password…) et saisir le code. Ensuite : créer une boutique et son domaine, l'ouvrir, régler sa marque (gabarit, couleurs, polices, textes) avec l'aperçu, importer un catalogue (le modèle CSV se télécharge depuis la page d'import), puis **ses photos** : « Déposer les photos », un dossier ou un .zip de photos nommées d'après les références (`PP18-KIT.jpg`, `PP18-KIT-2.jpg`) ; le rapport montre ce qui va où avant l'envoi, et un envoi se retire d'un geste.

**Donner l'accès au backoffice** — dans la console, fiche de la boutique → **Gérer l'équipe** : saisir une adresse (inventée, par exemple `papa@maymar.test`) et un rôle, **Inviter**. La console affiche le lien d'accès à envoyer (boutons « Envoyer par WhatsApp » et « Envoyer par e-mail »). L'ouvrir dans une **fenêtre de navigation privée** (sinon il remplace ta session de console) : choisir un mot de passe, et l'on arrive dans le backoffice de la boutique — un propriétaire se voit d'abord proposer la double authentification (« Plus tard » la reporte). Depuis la liste : changer le rôle, retirer l'accès (la personne est dehors aussitôt), le rendre, ou remettre un lien si le mot de passe est oublié.

**Les prospects** (console, menu Offre → **Prospects**) — les commerces à qui vendre : « Nouveau prospect » (le commerce, qui appeler, son téléphone, sa ville, son métier, la prochaine action et sa date ; l'e-mail, d'où il vient et une note sont repliés dessous). La liste met le plus pressé en tête : une relance en retard s'écrit en rouge, celle du jour en ambre, et le menu compte celles du jour. Sur chaque ligne : **Appeler**, **WhatsApp** ; « Étape, prochaine action, fiche » : changer l'étape suffit (à contacter, contacté, démonstration montrée, offre faite, gagné), **Perdu** demande un motif. À la démonstration ou à l'offre, **Créer sa boutique** ouvre l'assistant déjà rempli (nom, identifiant, personne à appeler, téléphone, métier) ; créée, la boutique fait passer le prospect « gagné » et s'y rattache. Le journal (genre « Prospects ») garde chaque geste.

**Les e-mails de commande** (coupés par défaut) — au backoffice, Réglages → **Commandes** : « Les e-mails au client » → **Un e-mail à chaque étape** (reçue, confirmée, expédiée avec le transporteur et le numéro de suivi, livrée, annulée ; aux couleurs de la boutique, à l'adresse de son compte ou à celle que l'équipe a notée ; jamais pour une vente au comptoir), et « Prévenir l'équipe » → **Aussi par e-mail** (chaque commande de la vitrine part au propriétaire et aux administrateurs, avec le lien pour l'ouvrir). Pour essayer : saisir une commande (Commandes → Saisir une commande) avec une adresse e-mail, puis lire l'e-mail en local sur http://127.0.0.1:54321/email-dev/rendu/dernier?email=<l'adresse>. Dans la console, **E-mails** montre les quatre modèles (« La commande ») aux couleurs de chaque boutique. Un envoi manqué est retenté, cinq fois au plus.

**L'état technique** (console, menu Administrer → **État technique**) — ce qui fait tourner la plateforme, relu à chaque ouverture : la base (temps de réponse, taille, connexions), les e-mails (le fournisseur, le crochet de Supabase Auth, les envois et refus de la semaine, la file des e-mails de commande), SkanFact (chaque secret « posé » ou « manque », jamais sa valeur ; les boutiques connectées ; les envois en attente ou refusés), les fichiers (R2 ou le relais local), et les domaines. En haut, le verdict : « Tout répond » ou les points à regarder, avec un lien vers chaque carte. **Vérifier les domaines maintenant** fait une vraie requête HTTPS vers chaque domaine en ligne et note le résultat (certificat valable, ou la raison de l'erreur) ; un domaine en erreur remonte aussi dans « À surveiller ». En local, les domaines en « .localhost » ne se vérifient pas.

**La consommation** (console, menu Piloter → **Consommation**) — ce que chaque boutique envoie ce mois-ci, e-mails et SMS, face à son quota, relu tout seul toutes les 30 secondes (« En direct » ; « En pause » pendant une saisie ou quand une ligne est ouverte). En haut, la plateforme face au forfait de son fournisseur, les boutiques au-delà de leur quota, les refus. Puis chaque boutique, la plus proche de son quota d'abord : une jauge par canal (verte, ambre à 80 %, rouge au-delà) et ce qu'il reste, ou la fin du mois au rythme actuel. **Cliquer une ligne** l'ouvre : le détail du mois (codes de connexion, suivi des commandes, accès de l'équipe, lettre), six mois d'historique, et — super-administrateur — l'exception de la boutique (vide : sa formule), ce qui se passe au dépassement, et un crédit pour le mois. En bas, les quotas des formules et leur prix au-delà, et le forfait du fournisseur. Pour essayer : fixer 2 000 e-mails à Essentiel, ouvrir Maymar, lui donner 150 SMS « Codes par e-mail », puis baisser à 1 : sur sa vitrine, « Mes commandes » ne propose plus que l'adresse e-mail. Remettre ensuite les champs à vide.

**Les e-mails : qui envoie, au nom de qui, où vont les réponses** (console, menu **E-mails** → **Envoi**) — l'expéditeur de la plateforme (fournisseur, adresse, domaine ; la clé n'apparaît jamais), ce qui est parti ce mois-ci, l'adresse où vont les réponses des équipes, un **envoi d'essai** (choisir une boutique et un modèle : il part comme un vrai e-mail, le sujet commence par [Essai]) et la liste des boutiques. Puis, sur une boutique, l'onglet **E-mails** : en haut, ce que voit le client (« De », « Répondre à ») ; régler le nom affiché et l'adresse de réponse (le bouton « Répondre à … » reprend l'e-mail de ses mentions légales) ; **Envoyer depuis son domaine** : écrire le domaine (proposé : celui de la vitrine), « Ajouter », poser les enregistrements DNS affichés (Copier) chez le registrar ou Cloudflare, « Vérifier maintenant », puis « Envoyer depuis commandes@… ». Un essai envoyé ensuite part de cette adresse. « Couper » ou « Retirer le domaine » ramènent l'adresse de SkanEcom. Sur l'aperçu en ligne, rien ne part : les enregistrements sont des exemples.

**Le paiement en ligne (Konnect)** — coupé par défaut. Dans la console (`admin@skanecom.test`), fiche de Maymar → **Modules** : allumer « Paiement en ligne ». Au backoffice (`gerant@maymar.test`), Réglages → **Paiement** → « Votre compte Konnect » : un portefeuille (par exemple `5f7a209aeb3f76490ac4a3d1`) et une clé (en local, n'importe quelle clé de 16 caractères ; une clé qui contient `refusee` est refusée), **Brancher mon compte Konnect**, puis allumer « Paiement en ligne (Konnect) » et Enregistrer. Sur la vitrine de Maymar, commander en choisissant **Payer en ligne** : la page de paiement de Konnect est simulée telle quelle (carte bancaire ou e-Dinar). Cartes d'essai : `4242 4242 4242 4242` acceptée, `4000 0000 0000 0002` refusée par la banque (toute date à venir, tout code à 3 chiffres ; une carte e-Dinar qui finit par `0002` est refusée aussi). Refusée, ou **Annuler et revenir à la boutique** : la page de fin propose de réessayer ou de payer à la livraison ; acceptée : « Votre paiement est reçu ». Au backoffice, la fiche dit « Payée en ligne » et le bordereau « Rien à encaisser » ; une commande dont le paiement n'a pas abouti propose « Il paiera à la livraison ». « Retirer le compte » remet tout comme avant.

**La facture au nom d'une société** — coupée par défaut, allumée sur la Quincaillerie du Sud. Au tunnel, cocher « Je veux une facture au nom d'une société » : raison sociale, matricule fiscal (`1234567A/M/000` ; un matricule illisible est refusé avant l'envoi), adresse de facturation (celle de la livraison, ou une autre). La page de fin dit « Facture au nom de ». Au backoffice, la fiche de la commande a sa carte **Facture** : corriger, ou « Revenir au nom de la personne » (au journal) ; une facture déjà émise dans SkanFact ne se corrige plus d'ici. Réglages → Commandes → « La facture » l'allume pour une autre boutique.

**La surveillance** — console, Administrer → **État technique** → « Surveillance des vitrines » : le dernier passage (chaque heure en ligne, par le déclencheur planifié du Worker), ses défauts (une vitrine qui ne s'ouvre pas, lente, des e-mails de commande ou des factures SkanFact coincés, un domaine d'envoi qui n'est plus vérifié), la disponibilité de chaque vitrine sur 24 heures, et **Vérifier maintenant**. En local, le passage de l'heure se lance à la main : `curl "http://127.0.0.1:4200/cdn-cgi/local/scheduled?cron=0+*+*+*+*"`. Une vitrine en panne remonte en rouge dans « À surveiller ».

**Les revenus** (console, menu Piloter → **Revenus**) — le revenu mensuel attendu (le prix de la formule de chaque boutique ouverte, hors démonstration), les boutiques payantes, ce qui viendra à l'ouverture des boutiques en préparation, et ce que SkanFact a dit à la dernière lecture (le reste à encaisser, l'échu, les retards). Rien n'est estimé : tant qu'une formule est « Prix à fixer », ses boutiques ne comptent pas et la page le dit ; les prix se fixent dans **Formules**. Par boutique : sa formule, son prix, et sa situation SkanFact (à jour, à payer, en retard, ou non reliée).

**Nouvelle boutique, en cinq étapes** — depuis le bouton de l'accueil : **Le client** (nom, identifiant tiré du nom ; la personne à appeler et son téléphone, facultatifs, vont sur sa fiche), **Le domaine** — « Il a déjà son domaine » (un .tn acheté chez un registrar : sa fiche dira les deux enregistrements à poser, le CNAME et le TXT, prêts à copier, puis « Relire chez Cloudflare »), « Une adresse pour commencer » (`<identifiant>.localhost` en local, `<identifiant>.skanecom.tn` en ligne, le temps d'avoir le sien) ou « En acheter un » (super-administrateur : « Vérifier » dit s'il est libre et son prix — en local, un nom qui contient « pris » est déjà pris, un .tn n'est pas vendu par Cloudflare ; puis la case « J'achète … pour … par an » ; l'achat part à la création, au journal avec son prix) —, **Le métier** (un préréglage, ou partir de zéro), **L'apparence** (la structure, posée par le métier s'il y en a un), **L'offre** (la formule, démonstration ou cliente) et le récapitulatif « Avant de créer ». « Continuer » vérifie l'étape (sans nom, elle ne passe pas) ; Entrée dans un champ passe à la suivante, rien n'est créé avant « Créer la boutique » ; la rangée du haut ramène à une étape, la saisie gardée. **Marque → Couleurs** : neuf palettes prêtes d'un clic, la couleur principale (pastilles ou nuancier), et la lisibilité mesurée dessous — un jaune sur fond clair est signalé « trop pâle » ; les treize couleurs une à une restent repliées dessous.

**L'accueil de la console** — quatre chiffres en tête (les clientes seules), puis **À surveiller** : ce qui presse d'abord (rouge, puis ambre), et sur chaque ligne **Plus tard** (au clavier : Tab jusqu'à « Plus tard », Entrée, Tab, Entrée) : « Jusqu'à demain » ou « Pendant une semaine », pour toute l'équipe ; le signal revient seul, ou plus tôt s'il s'aggrave ; « mis à plus tard » les garde à part, avec « Reprendre ». Les simples informations (sans formule, sans client SkanFact, en préparation…) sont repliées en une ligne, une pastille par boutique. Le compteur rouge à côté de « Boutiques », dans le menu, dit combien de points pressent. Le menu est rangé par usage (Piloter, Offre, Communiquer, Administrer) ; « Nouvelle boutique » est le bouton de l'accueil. Trier les boutiques (ce qui attend d'abord, nom, commandes, les plus récentes, mise en place) : changer la liste suffit ; **Exporter la liste (CSV)** emporte ce que montre le filtre, dans cet ordre.

**L'abonnement du commerçant** — au backoffice (`gerant@maymar.test`), Réglages → tuile **Abonnement** (ou Ctrl+K, « Abonnement ») : sa formule (Maymar est « sur mesure » : tout est ouvert), ce qu'elle ouvre, ses envois du mois. Ses factures SkanEcom paraissent une fois Maymar reliée à son client SkanFact dans la console (fiche → Facturation) ; avant, l'écran le dit. Avec une formule (console, fiche → Formule : « Essentiel »), les fonctions hors formule portent la formule qui les ouvre. Un préparateur (`prepa@quincaillerie.test`) n'a ni la tuile ni la page.

**La fiche d'une boutique** — en tête, une ligne **À faire maintenant** (le signal le plus pressant, sinon l'étape suivante de la mise en place) ; puis **Le client** : noter la personne à appeler, son téléphone (« 20 123 456 » suffit), son WhatsApp s'il diffère, son e-mail, son matricule fiscal, son adresse, un mot ; ensuite « Appeler », « WhatsApp » et « E-mail » d'un geste. Une boutique ouverte replie sa mise en place sous son avancement. Au téléphone, les onglets s'estompent au bord quand il en reste à faire glisser. **Suspendre la boutique** demande pourquoi (abonnement impayé, à sa demande, contenu à corriger, sécurité, autre) et un message à son équipe : au backoffice de la boutique (`appels@maymar.test` pour Maymar), un bandeau rouge le dit en tête de chaque page tant que dure la suspension ; « Ouvrir la boutique » l'efface.

**Les accès de chacun** — **Mot de passe oublié ?** sur la page de connexion (l'adresse déjà tapée suit) : un lien part par e-mail (en local, le dernier e-mail d'une adresse se lit sur http://127.0.0.1:54321/email-dev/rendu/dernier?email=appels@maymar.test) ; la page dit la même chose que l'adresse ait un compte ou non, et une deuxième demande dans les deux minutes ne part pas. **Mon compte** : un clic sur son nom, en bas de la barre latérale (au téléphone, dans le menu) — changer son mot de passe (l'actuel d'abord), **Créer mes codes de secours** (dix codes montrés une fois : les copier, les imprimer, « C'est noté » ; « Remplacer mes codes » demande confirmation), « Se déconnecter de tous les appareils » (les autres onglets retombent sur la connexion). Puis, déconnecté : se reconnecter avec le mot de passe, et à la double authentification « Téléphone perdu ? Utiliser un code de secours » — un code (majuscules, tiret facultatifs) retire l'ancienne application, la page propose d'en enregistrer une nouvelle et dit combien de codes restent ; un code déjà servi est refusé ; cinq essais manqués ferment la porte un quart d'heure. Les liens d'invitation et de mot de passe (équipe SkanEcom, équipe d'une boutique, côté console comme côté propriétaire) ont un bouton **Envoyer par e-mail** : celui d'une boutique part à son nom et à ses couleurs.

**La double authentification, facultative par défaut** — à la connexion, elle est proposée à l'équipe SkanEcom, aux propriétaires et aux administrateurs : **Plus tard** la reporte un mois sur cet appareil (pour ce compte seulement) ; **Mon compte → Activer la double authentification** l'active quand on veut (« Annuler » y ramène), puis la page propose les codes de secours. Qui a enregistré une application donne toujours son code, sans « Plus tard ». Deux réglages la rendent obligatoire, coupés par défaut : dans la console, **Équipe SkanEcom → Double authentification de l'équipe** (super-administrateur ; « Exigée de toute l'équipe » : une recrue l'enregistre avant d'entrer) ; au backoffice, **Équipe → Double authentification** (le propriétaire, pour le propriétaire et l'administrateur ; il doit d'abord avoir activé la sienne, sinon c'est refusé). Le journal garde chaque changement.

**Entrer dans le backoffice d'un client (support)** — dans la console, onglet **Support** d'une boutique : dire pourquoi on entre, choisir « Regarder » ou « Agir comme un administrateur » et une durée, **Entrer dans son backoffice**. On y arrive avec un bandeau noir en haut (le mode, l'heure de fin, le motif) et **Fermer l'accès** ; échu ou fermé, le backoffice renvoie à la console. Le propriétaire (`gerant@maymar.test`) retrouve chaque accès dans **Équipe → Le support SkanEcom**, et peut fermer un accès encore ouvert.

**Piloter la plateforme** (console, `admin@skanecom.test`) — **Formules** : la matrice de ce que chaque formule ouvre (Essentiel, Pro, Complète ; les prix restent « à fixer ») ; cocher, nommer, Enregistrer ; « Nouvelle formule » ajoute une colonne ; en descendant, une bande fine redit le nom des formules au-dessus de leurs colonnes. Sur la fiche d'une boutique, carte **Formule** : passer Maymar en Essentiel — la carte dit ce qui s'éteint ; au backoffice de Maymar, Réglages → Fonctions de la vitrine, les fonctions hors formule portent une clé « Formule Pro » et ne s'allument plus ; l'onglet Modules de la console dit « Hors formule · Vient avec … ». Revenir « Sur mesure ». **La formule d'une boutique, personnalisée** (onglet **Formule** de sa fiche) : elle part de sa formule (ou de « sur mesure », tout ouvert), puis chaque droit se coche ou se décoche pour elle seule ; la pastille de chaque ligne suit la case avant même d'enregistrer (« Dans la formule », « Ajouté », « Retiré », « Hors formule ») ; « Son prix » remplace celui de la formule (Revenus le compte, la ligne dit « son prix » et « personnalisée ») ; « Revenir à la formule » efface les écarts. Dans l'onglet **Modules**, un module hors formule a « Lui ouvrir et activer » (un écart, d'un geste). Dans **Nouvelle boutique**, l'étape « L'offre » propose les modules à activer dès la création : coché hors de la formule choisie, il est dit « lui sera ouvert en plus ». **Tableau de bord** : le chiffre livré, les commandes, le taux de refus et le panier moyen sur 7, 30 ou 90 jours, comparés à la période d'avant, jour par jour puis boutique par boutique (« Avec les démonstrations » les ajoute). L'accueil de la console, **À surveiller**, signale un taux de refus élevé, une boutique sans commande depuis 14 jours, un SAV ou un devis qui attend, des avis à relire, un certificat en erreur, une boutique ouverte sans formule. Sur la fiche d'une boutique : **Suivi** (une note épinglée en tête, que seule la console voit ; « Me le rappeler le » : le jour venu, la note passe en tête et remonte dans À surveiller jusqu'à « C'est fait ») et **Cycle de vie** (renommer — l'adresse reste —, « Nouvelle boutique à partir de celle-ci » reprend son apparence, ses réglages, sa livraison et ses rayons, sans images ni catalogue ni clients ; fermer, la case cochée) ; dans **Domaines**, « Rendre principal » et « Retirer ». **Annonces** : publier une nouveauté ou une maintenance ; elle paraît en haut du backoffice de chaque boutique visée, chacun la ferme (×) pour soi ; « Arrêter » la retire. **Équipe SkanEcom** : inviter au rôle support (la console rend le lien), changer un rôle, retirer, « Réinitialiser la double auth » d'une personne qui a perdu son téléphone (ses sessions tombent ; aussi depuis l'équipe d'une boutique) ; le support lit tout, sans engager (formules, modules, statut, retrait d'un domaine, équipe : super-administrateur seulement). **Journal** : chaque geste de la plateforme, filtré par boutique, par genre et par période (du… au…), « Exporter (CSV) » emporte ce que montre le filtre (l'export est lui-même tracé) ; l'onglet **Envois** liste chaque e-mail sorti (l'adresse masquée) et dit les refus — un refus dans la semaine remonte dans À surveiller. Le **Tableau de bord** s'exporte aussi, une ligne par boutique.

## 4. Les vérifications automatiques

La CI a deux niveaux, pour ne pas attendre vingt minutes à chaque envoi :

- **À chaque envoi** (quelques minutes) : les tests de la base, puis la vérification rapide de la vitrine — types, relecture (eslint), compilation, essais de cache et d'isolation.
- **La vérification complète** (les parcours « humains » avec leurs captures) : les cinq parcours tournent **en parallèle**, chacun sur une base neuve. Elle part sur une demande de fusion, sur `main`, à la main (Actions → Vitrine → **Run workflow**), ou quand le dernier message d'envoi contient **`[complet]`** — à mettre après un très gros lot. Les captures sont à télécharger dans les artefacts du passage (`captures-humain`, `captures-gestion`…).

Un nouvel envoi sur la même branche annule la vérification encore en cours du précédent.

Pendant le développement d'un lot, on vise juste — la section touchée, pas tout :

```bash
outils/base-locale.sh tester 75 43             # ces fichiers de supabase/tests seuls
cd application && bun run typecheck && bun run lint
SECTIONS=4 bun run parcours                    # une section du parcours « humain » (ou SECTIONS=1,maison)
SECTIONS=4bis,6 bun run parcours:gestion       # idem au backoffice
```

Tout, à la main (avant un `[complet]`, ou pour reproduire la CI). Les tests de la base se suffisent à eux-mêmes ; le reste demande la vitrine lancée par `outils/essayer.sh` dans un autre terminal, et une base neuve entre deux parcours (certains publient des modifications) :

```bash
outils/base-locale.sh tester                   # 1959 tests de la base (isolation des boutiques, vitrine, console, import, commande, backoffice, équipes, catalogue, photos, réglages, clients, pages légales, modules, accès support, devis, avis clients, sections de l'accueil, facturation SkanFact, saisie des commandes, vente au comptoir, gestes groupés, packs, précommandes, listes paginées…)
outils/essai-vitrine.sh                        # les boutiques ne se mélangent jamais, le tunnel et le compte ne sont jamais en cache
cd application
bunx playwright-core install --with-deps chromium   # une fois (demande sudo)
bun run parcours                               # le testeur « humain » : souris, clavier, téléphone
bun run parcours:console                       # la console SkanEcom : créer, régler, importer une boutique
bun run parcours:commande                      # une vraie commande dans chaque gabarit (base fraîche : outils/essayer.sh)
bun run parcours:gestion                       # l'équipe de Maymar traite ses commandes au backoffice
bun run apercu                                 # captures des pages clés des boutiques
bun run essai:skanfact-reel                    # contre un VRAI SkanFact d'essai (cadrage 06, § 4 ter : SKANFACT_REEL)
```

Les captures arrivent dans `.outils/captures/` (à la racine du dépôt).

## En cas de souci

| Message | Que faire |
|---|---|
| `✗ Postgres 16 introuvable` ou `pgTAP manque` | `sudo apt install postgresql-16 postgresql-16-pgtap` |
| `✗ Node … Node 22 au moins est attendu` | `nvm install 22 && nvm use 22` |
| `✗ Le port 4200 est déjà pris` | une vitrine tourne déjà (Ctrl+C dans son terminal), ou `PORT_VITRINE=4300 outils/essayer.sh` |
| `Le port 54321 est déjà pris` ou `Le port 54322 est déjà pris par une autre base` | une autre copie de SkanEcom tourne, depuis un autre dossier : `outils/essayer.sh arreter` dans ce dossier-là, puis relancer |
| `Ce cluster n'a pas de superutilisateur supabase_admin` | `outils/base-locale.sh detruire`, puis relancer |
| La compilation échoue | la fin du journal s'affiche ; le journal complet est dans `.outils/essayer.log` |
| La page dit « Adresse inconnue » | ouvrir l'adresse avec le nom de la boutique : `mode.localhost:4200`, pas `localhost:4200` |
